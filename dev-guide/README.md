- 사용자가 요청하지 않으면 **게임 코드를 수정하지 않는다**. 질문은 필요할 때 하나씩 한다.

## 폴더 구분
- `/docs`: 기획 원본 및 확정/미확정 기록 (원본 보존).
- `/dev-guide`: 구현 범위, 아키텍처, 테스트, 미확정 처리 원칙.
- `/game`: 브라우저에서 직접 실행할 수 있는 웹게임 코드.

## 개발 원칙
1. 사용자가 확정한 규칙만 게임 규칙으로 사용한다.
2. 실제 수치가 미확정이면 **데모용 임시 값**으로 분명하게 표시하고 게임 확정값으로 저장하지 않는다.
3. 전투와 탐험은 **한 행동 시계**를 공유한다. 탐험 중 한 이벤트 또는 전투 중 한 포켓몬의 행동 차례마다 한 번 진행한다.
4. 게임 엔진(확률 추첨, 상태 변화)과 UI(표시 및 조작)를 분리한다.
5. 포켓몬의 종족별 출현 비중은 **전역 단일 값**이다. 세부 지역에는 등장 종족만 지정한다.
6. 한번의 조우에서 같은 종족 중복을 허용한다.
7. 모바일 화면에서도 문서와 화면이 사용 가능하도록 구성한다.
8. 임시 시연 콘텐츠와 확정 기획을 구분한다.


## UI 성능 규칙 — 부분 갱신 필수
- **페이지 전체 재로드 금지**: 게임 진행, 타이머, 전투, 로그, 알림, 인벤토리 변경을 이유로 `location.reload()` 또는 전체 페이지 재구성을 하지 않는다.
- **필요한 화면 부분만 변경**: 상태 변경에 영향을 받는 요소의 텍스트·스타일·버튼 상태만 실제 값이 다를 때 수정한다.
- **기존 DOM 노드 유지**: 같은 포켓몬 카드/보관함 행은 재사용하고 HP·상태·개수만 바꾼다. 포켓몬이 등장하거나 사라질 때만 해당 노드를 삽입·삭제한다.
- **로그/알림은 증분 처리**: 새 기록 하나를 앞에 추가하고, 개수 상한 초과 때 마지막 기록만 제거한다. 지우기 버튼을 누를 때만 해당 목록 전체를 비운다.
- **타이머 표시만 짧은 주기로 갱신**: 카운트다운 숫자와 진행 막대는 시계가 움직일 때 갱신하되, 다른 UI와 연동해 매번 재생성하지 않는다.
- **보관함은 이벤트 기반**: 획득·손실·귀환·출발 등 보유 아이템이나 소속이 변할 때만 보관함 패널을 갱신한다.
- **플레이어 조작 상태 보존**: 미변경 카드, 체크박스 선택, 스크롤 위치, 포커스 및 모달 상태는 관련 업데이트가 아니라면 유지한다.
- **데이터 변경과 화면 변경 분리**: 게임 엔진은 상태 변경을 담당하고, 렌더링 함수는 필요한 요소에만 패치를 적용한다.
- 신규 기능에서도 위 원칙을 유지하고, 모든 페이지/탭을 일괄 새로고침하는 전역 렌더링 함수를 만들지 않는다.


## 확정 — 모바일 우선 UI 구성 (2026-11-12)
- **모바일 우선 설계**. PC는 같은 상단바/중앙 콘텐츠/하단 메뉴 구조에서 가로 공간을 확장하지만, 전체 앱 최대 너비는 **1400px**로 제한하고 중앙 정렬한다.
- 화면은 세 영역으로 나눈다: **상단 고정 바 / 중앙 콘텐츠 / 하단 고정 메뉴**.
- 상단바는 최소 높이. **좌측 돈(윗줄)·에너지(아랫줄)**, **우측 알림 아이콘·설정 아이콘**.
- 돈과 에너지는 **표시 전용**(클릭 동작 없음)이며 데이터 변경 시 해당 숫자만 갱신한다. 실제 경제 값은 미확정으로, 프로토타입에서는 숫자를 만들어내지 않는다.
- 알림 아이콘은 **최근 30개 알림 기록 팝업**, 설정 아이콘은 **설정 팝업**을 연다. 팝업의 **최종 표시 형태(중앙 모달/바텀시트/전체 화면)는 미정**. 현재 브라우저 내장 dialog는 임시 구현이다.
- 하단 메뉴는 **마을 / 포켓몬 / 탐험 / 기록**의 **4개 아이콘+이름**. 선택 탭은 시각적으로 구별한다.
- 탭을 바꾸면 **중앙 콘텐츠만 전환**하고 기존 탭 DOM과 화면 상태(체크·선택·스크롤 등)를 보존한다. 이미 선택한 탭을 **다시 누르면 그 탭만 맨 위로 스크롤**, 내용과 데이터는 초기화하지 않는다.
- 각 탭은 **독립적인 세로 스크롤 위치**를 보존한다. **전체 페이지 및 가로 스크롤 금지**, 중앙 콘텐츠 내부에서만 세로 스크롤한다.
- 중앙 콘텐츠는 주어진 공간을 **전체 활용**하며, 메뉴별로 필요한 여백만 자체 적용한다. 전 메뉴 공통 여백 강제 금지.
- 기존 확정 **부분 갱신 원칙**을 그대로 적용한다. 탭 전환 또는 공통 타이머 동작 때문에 불필요하게 전체 페이지를 재구성하지 않는다.

### 구현 현황 및 후속 과제
- `game/index.html`: 상단 자원/팝업·중앙 4탭·하단 메뉴로 변경.
- `game/style.css`: 100dvh 화면 내부 스크롤, 모바일 우선, PC 1400px 상한 적용.
- `game/ui/navigation.js`: 탭별 scrollTop 보존, 재탭 시 맨 위 이동, 팝업 열기·닫기.
- `game/ui/exploration-detail.js`: 3슬롯 준비창 및 포켓몬 선택창.
- `game/game.js`: 화면 초기화·로그/알림·게임 타이머 호출.
- 마을·포켓몬·기록의 구체적 기능, 실제 돈/에너지 수치, 최종 팝업 형태는 **미확정 또는 미구현**. 프로토타입은 설명용 임시 콘텐츠만 표시한다.

## 확정 — 탐험 탭: 지역 카드 → 개별 상세창
- 탐험 탭에는 각 지역을 카드로 나열한다. 카드 클릭 시 해당 지역의 탐험 상세창을 연다.
- 카드에는 지역명·파견 포켓몬·현재 진행 상태·진행률·전리품을 표시한다.
- 상세창에서 해당 지역의 현재 세부 지역, 포켓몬/적군, 로그, 진행률을 확인하고 탐험 출발·후퇴·닫기를 조작한다.
- **닫기는 탐험을 중단하지 않는다.** 후퇴는 해당 지역 탐험만 종료한다.
- 여러 지역을 동시에 탐험하되 동일 지역에는 탐험 하나만, 같은 포켓몬의 중복 파견은 금지한다.
- 각 지역별 독립 타이머를 사용하지만 간격은 전 지역 공통 강화 수치(기본 3초, 2초, 1초)를 따른다. 동일 지역에서는 탐험·전투가 하나의 타이머를 공유한다.
- 지역 카드 목록은 스크롤을 유지하고 **개별 카드·상세 정보만 부분 갱신**한다.
- **임시값:** 최초 2개 지역의 실제 세부지역·출현표, CSS 배경 및 일부 회복·아이템 수치. 전투는 이미 능력치 기반 피해량 계산 엔진을 사용. 지역 카드의 포켓몬은 텍스트 아바타이며, 선택창 포켓몬 이미지는 외부 PokeAPI 스프라이트를 임시 사용한다. 실제 이미지와 지역/스탯은 승인 전까지 확정하지 않는다.
- **미결정:** 탐험 상세창의 최종 팝업 형태, 카드의 구체적 우측 아이콘 구성, 전투 시 화면 세부 배치.
- [개발 구조·검증 가이드](implementation-plan.md#지역-목록--탐험-상세창-ui-개편-2026-11-12)

## 확정 — 탐험 준비창 및 포켓몬 선택창 (2026-11-12)

- 빈 지역을 누르면 **최상단 지역 이름 + 세로 슬롯 3개**로 구성된 탐험 준비창.
- 빈 슬롯 클릭 → 포켓몬 선택창, 배치된 슬롯 클릭 → 해당 개체 즉시 해제.
- 1~3마리만 출발 가능. HP 100% 미만이나 다른 지역에 파견 중인 개체는 선택 불가. 동일 개체 중복 배치 금지.
- 준비창 닫기 → 배치 초기화. 포켓몬 선택창만 뒤로 가기 → 기존 슬롯 배치 유지.
- 포켓몬 선택창은 **모든 보유 개체** 표시. 선택 불가 개체도 어둡게 표시하고 클릭하면 선택 불가 사유 안내.
- 기본은 **아이콘 이미지만 4열**, 전환 버튼으로 **한 줄 1마리 목록형**. 아이콘형에는 이름·레벨·HP 등의 텍스트를 표시하지 않는다.
- 정렬: 획득 순서(기본) / 레벨 / 도감번호, 오름차순/내림차순. 정렬·표시 모드는 창을 다시 열어도 유지한다. 검색 없음.
- 개체 선택 시 해당 슬롯에 즉시 배치하고 선택창을 닫는다.
- **현재 레벨/경험치 엔진은 구현됨**. 이전 레벨 미구현 안내는 과거 프로토타입 설명이다. 최신 구현 현황은 [인수인계](handoff.md) 참조.
- [개발 인수인계](handoff.md)와 [구현 계획·회귀 테스트](implementation-plan.md) 참조.

## 첫 구현 범위
- 시작점이 정해진 지역과 여러 세부 지역, 방향성 연결, 목적지별 행동 확률.
- 종족별 전역 고유 출현 비중을 이용한 적 독립 추첨.
- 전투·탐험 공통 3초/2초/1초 행동 간격(강화 버튼은 **시연용**, 비용·해금 조건 미구현).
- 스피드 내림차순 턴, 동속 무작위, 라운드 단위 정렬, 기절자 턴 생략, 부활 후 다음 라운드부터 행동하도록 확장 가능한 엔진.
- 이벤트 로그, 지역별 탐험 시작·귀환, 전리품 개별 보관함, 기절 손실, **전멸 시 탐험 종료·남은 전리품 정산**.
- 지역 해금 규칙 및 능력치 기반 피해량 계산은 구현됨. 보스 실제 전투, 알·생활 등 미승인 콘텐츠는 후속 개발.

**초기 플레이 가능한 프로토타입**이다. 실제 포켓몬 데이터·지역·시간 이외의 경제/밸런스·전투 피해 공식은 완성된 게임 규칙이 아니다.

## 안정성 및 자동 테스트 (2026-11-12)
- `game/engine/core.js`: 데이터 정합성 검사 및 미확정 시연 데이터 구분.
- `game/engine/exploration.js`: 잘못된 파티 입력 검증; 엔진 예외 시 해당 지역만 오류 모드로 중단, 자산·위치 유지.
- `game/ui/exploration-detail.js`: 포켓몬 선택 DOM 재사용 및 상세창 렌더 통합.
- `tests/engine.test.cjs`: `node --test tests/*.test.cjs`로 엔진 회귀 테스트.
- `.github/workflows/test.yml`: main 및 PR 코드 변경 시 자동 테스트.
- 오류 중지 후 자동 재개 기능은 추가하지 않았으며 현재 수동 후퇴만 가능. UI 실기기 회귀 테스트는 별도.

## Pages 404 재발 방지 (2026-11-12)
- **실제 GitHub 설정에서** `Settings → Pages → Build and deployment → Source`를 `GitHub Actions`로 선택해야 한다. 저장소 파일 수정만으로 이 웹 UI 설정을 바꿀 수 없다.
- 배포는 `.github/workflows/deploy-pages.yml` 한 경로를 표준으로 사용한다. GitHub의 `pages build and deployment`가 별도로 실행되면 Settings의 Source를 확인한다. 별도 실행 로그만으로 충돌 원인을 확정하지 않는다.
- `scripts/prepare-pages.sh`는 `_site/index.html`, `_site/game/`, 이전 주소 호환용 `_site/게임/index.html`, `deploy-revision.txt`를 생성한다.
- `tests/pages.test.cjs`에서 배포 아티팩트 진입 파일과 HTML 내부 JS/CSS 경로를 검사하고, 엔진 테스트가 통과해야만 배포한다.
- 배포 후 `scripts/check-live-pages.sh`가 대표 URL·게임 HTML·리소스·기존 경로의 HTTP 200과 배포 커밋 SHA를 제한된 재시도로 확인한다. 이 검사 통과만으로 실제 UI 동작을 보장하지 않는다.
- **주의:** 이미 저장된 과거 `/게임/` 링크는 호환되도록 배포 아티팩트에 리다이렉트를 생성한다. `main`의 게임 코드 폴더는 계속 영문 `game/`을 사용한다.
