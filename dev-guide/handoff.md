## 현재 완료된 작업 — 게임 코드 구조
```text
game/
  index.html                 상단·중앙 4탭·하단 네비 / 팝업 구조
  style.css                  모바일 우선 스타일, 4열 포켓몬 아이콘
  data.js                    임시 포켓몬 및 지역 데이터
  game.js                    게임 UI 초기화, 로그·알림, 타이머 연결
  engine/
    core.js                  전역 로스터, 지역별 상태, 이벤트 발행
    exploration.js           지역별 탐험, 출발/후퇴/회복/행동
    combat.js                시연용 전투, 라운드/스피드 순서
  ui/
    navigation.js            탭·스크롤 유지, 팝업 열기/닫기
    exploration-list.js      지역 카드 목록, 진행률 부분 갱신
    exploration-detail.js    탐험 상세·준비창 3슬롯·포켓몬 선택창
```
- `data.js`에 **시연 지역 2곳**(바람의 들판, 시연용 초원), **시연 파트너 3마리**(피카츄, 이브이, 구구)가 있다. 지역명·종족 가중치·보상·능력치·HP·피해량은 확정 밸런스가 아니다.
- 별도 정식 레벨 데이터나 저장 시스템은 아직 없다.
- 지역별 `state.regions[id]` 독립 상태: `mode`, `locationId`, `party`, `enemies`, `round`, `order`, `turnIndex`, `actions`, `remainingMs`, `error`(오류 중지 시). 같은 개체 `expedition` 필드로 중복 출발 방지.
- 각 지역은 독립 카운트다운. 전 지역에 공통 속도 단계(3초 → 2초 → 1초, 강화는 테스트용). **한 지역 내 탐험/전투는 동일 타이머** 사용.
- 후퇴 시 그 지역만 종료하며 다른 지역은 진행 지속. 지역마다 한 탐험만 가능.
- 엔진 예외 발생 시 **해당 지역만 `error` 모드로 일시 중지**하고 포켓몬, HP, 전리품, 위치를 유지한다. 오류 중지 상태에서 사용자는 후퇴할 수 있다. **자동 재개/오류 상태에서 직접 재개는 아직 구현되지 않았다.**
- 페이지 전환과 팝업 열고 닫기는 탐험을 중단하지 않는다.

## 확정 공통 UI
- **모바일 우선**, 상단바/중앙콘텐츠/하단바 3구역. 상단·하단 고정, 중앙만 세로 스크롤, 가로 스크롤 없음.
- PC 전체 앱 최대 너비 **1400px** 중앙 정렬.
- 상단 좌측: 돈(윗줄), 에너지(아랫줄) 표시 전용, 현재 실제 수치 미연결. 우측: 알림·설정 아이콘.
- 하단 4메뉴: **마을 / 포켓몬 / 탐험 / 기록**, 아이콘+명칭 표시. 전환 시 탭별 DOM·입력·스크롤 상태 유지; 활성 탭 다시 누르면 해당 탭만 맨 위로 스크롤.
- 업데이트는 **부분 DOM 갱신**; 페이지 전체 새로고침/반복 재구성 금지.
- 팝업의 정식 표시 방식(중앙 모달/바텀시트/전체화면)은 **아직 미확정**. 현재 네이티브 `<dialog>`는 임시안.

## 확정 — 탐험 탭과 탐험 상세
- 탐험 탭은 **지역별 큰 카드 목록**. 카드에 지역 이름, 파견 포켓몬, 행동 상태, 행동 간격 진행률, 전리품 정보를 표시.
- 지역 카드를 누르면 **그 지역의 탐험 상세창**을 열고, 진행 중에는 현재 세부 지역/탐험·전투 포켓몬/HP/행동 기록/진행률/후퇴·닫기를 표시.
- 빈 지역을 누르면 **탐험 준비창**을 표시.
- 상세창 **닫기 ≠ 후퇴**: 닫아도 탐험은 계속되고, 후퇴는 해당 지역만 종료.
- 지역·세부 지역의 이미지, 카드 우측 상세 아이콘, 전투 중 포켓몬 배치 등은 아직 미정. 현재 CSS 임시 배경/프로토타입 카드.

## 확정 — 빈 지역 탐험 준비창
1. **최상단에 선택한 지역 이름**.
2. **세로 슬롯 3개**. 빈 슬롯을 누르면 포켓몬 선택창. 채워진 슬롯을 누르면 **즉시 해제**(확인창 없음).
3. 포켓몬 1~3마리 배치해야 출발. 0마리이면 탐험 시작 비활성화.
4. **동일 개체의 중복 배치 및 여러 지역 동시 파견 불가**. 각 개체의 현재 HP가 최대 HP와 동일해야 배치할 수 있다.
5. **탐험 준비창 닫기 → 모든 임시 슬롯 초기화**. 반대로 포켓몬 선택창만 뒤로 가면 기존 슬롯 배치를 유지.
6. 포켓몬을 눌러 선택하면 **즉시 해당 슬롯에 배치되고 선택창 자동 종료**, 준비창으로 복귀.
7. 팀 저장/불러오기 없음.
8. 슬롯의 순서가 전투 선행 순서를 정하지 않는다. 전투 행동 순서는 스피드 우선/동속 라운드별 추첨 규칙을 따른다.

## 확정 — 포켓몬 선택창
- **전체 보유 개체를 모두 표시**(선택 불가 개체도 숨기지 않음).
- HP 부족 / 다른 지역 파견 중 / 현재 다른 슬롯에 배치됨 → 어둡게 표시하고 **누르면 이유 안내**, 선택창은 그대로 유지.
- **기본 아이콘형**: **한 줄 4마리, 아이콘 이미지만** 보여 줌. 이름/레벨/HP 등 별도 텍스트를 아이콘 아래에 표시하지 않음.
- 버튼으로 **목록형** 전환: 한 줄 1마리, 이미지+이름+레벨+HP 등의 정보.
- 표시 방식(아이콘/목록)과 정렬 기준/방향은 **선택창을 닫아도 같은 실행 세션에서 유지**.
- 정렬: 획득 순서, 레벨, 전국도감번호. 오름차순/내림차순. **기본: 획득 순서 오름차순**.
- 검색창 **없음**. 정렬 추가(이름/전투력/능력치 등)는 추후.
- 레벨 데이터 아직 미구현이므로 **레벨 정렬은 현재 획득 순서 기반으로 동작**. 레벨을 만들어 넣지 말 것.
- 현재 아이콘 이미지는 `raw.githubusercontent.com/PokeAPI/sprites` **임시 외부 스프라이트** 사용; 실패 시 임시 글리프 대체. 사용자가 이전 게임에서 이미지 파일 매핑 구조를 선호했더라도, **현재 PokeTree 정식 리소스 연결은 아직 미완료**.

## 중요한 구분: 확정 기획 vs 임시 구현
- 확정 기획: 다중 지역 탐험, 지역/세부 지역별 이동 연결과 행동 확률 구조, 포켓몬 1~3마리, HP 100% 출발, 중복 배치 금지, 전투 스피드 정렬, 해당 지역 단일 행동 타이머 등. 자세한 원칙은 `docs/`의 원본을 확인할 것.
- 임시 구현: 시연용 포켓몬·지역·스탯·HP·피해량(아군 12/적군 9)·회복 8·보상명·출현 가중치·배경·이미지·경제 수치·타이머 강화 버튼 활성화 등. **최종 확정값으로 오인하지 않는다.**
- 아직 미구현: 정식 스킬/PP/전투 피해 공식/경험치, 보스/해금 조건, 알 부화와 자동화, 생활/경제, 정식 레벨, 영구 저장·재접속 복원, 정식 이미지 리소스.
- 인게임 알림 30개/전체 삭제/세션 초기화 등은 확정이나 주요 이벤트의 정식 발생 조건은 미완성.
- 포켓몬 선택 목록은 개체 ID별 DOM 버튼을 재사용하도록 변경했으며 선택창의 UI 요소가 모두 정상 동작하는지는 **실제 브라우저 포커스·스크롤·부분 갱신 검증**이 여전히 필요하다.

## 다음 대화에서의 권장 첫 작업
1. 먼저 사용자의 다음 지시를 듣고 **추가 규칙을 멋대로 확정하지 말 것**. 질문이 필요하다면 **한 번에 한 개씩**만.
2. 변경 전 **현재 `main`의 해당 파일을 읽고 SHA 확인**, 변경된 파일만 커밋한다. 아직 코드 수정 요청이 아니라면 GitHub 수정 금지.
3. 변경을 요청받으면 탐험 준비창의 모바일 UI/이미지·포켓몬 선택 작동 여부를 먼저 점검한다.
4. 회귀 테스트: 지역 카드 → 3슬롯 → 아이콘 4열 → 선택 즉시 배치 → 채워진 슬롯 해제 → 아이콘/목록 전환 → 정렬 유지 → 선택 불가 안내 → 뒤로가기와 준비창 닫기 각각의 동작 → 출발 → 상세창 닫고 탐험 계속 → 다른 지역 동시 파견 → 후퇴.
5. **GitHub Pages 404가 다시 나면** `.github/workflows/deploy-pages.yml`의 `_site/game/` 구조와 GitHub Actions 배포 상태부터 확인한다.
6. GitHub Pages는 정적 파일과 URL 기반. 사이트 확인 없이 배포 성공/실제 동작 성공을 단정하지 말 것.

## 대화 운영 원칙
- 사용자가 "수정하지 말고 설명해"라고 하면 코드·GitHub **변경하지 않는다**.

- 구현 후에는 무엇을 바꿨고 무엇은 미완료인지, 검증 범위가 무엇인지 명확히 보고한다.

## 2026-11-12 안정성·성능 정리 기록
- 입력: 포켓몬 출발 ID 중복/누락/존재 여부를 사전 검증한다.
- 데이터: `game/engine/core.js`의 `validateData()`가 행동/적 마릿수 확률 합계 100, 연결, 종족 참조, 보유 개체 ID를 검사한다.
- 탐험 오류: 다른 지역을 중단하지 않고 오류 지역만 일시 중지, 수동 후퇴 가능.
- UI: 포켓몬 선택 목록 버튼·이미지 재사용, 상세창 프레임 단위 렌더 통합, 숨겨진 탭 진행률 DOM 갱신 감소.
- 코드: 미사용 상태 변수와 로그 갱신 함수 정리, 팝업별 포커스 관리.
- 테스트: `tests/engine.test.cjs` (`node --test tests/*.test.cjs`), GitHub Actions `.github/workflows/test.yml` 자동 검사.
- **검증 한계**: 자동 테스트는 엔진·JS 구문 중심이다. 모바일/PC 화면의 실제 스크롤·포커스·팝업·동시 진행 체감 성능은 별도 브라우저 검증 필요.

## Pages 404 재발 방지 (2026-11-12)
- **실제 GitHub 설정에서** `Settings → Pages → Build and deployment → Source`를 `GitHub Actions`로 선택해야 한다. 저장소 파일 수정만으로 이 웹 UI 설정을 바꿀 수 없다.
- 배포는 `.github/workflows/deploy-pages.yml` 한 경로를 표준으로 사용한다. GitHub의 `pages build and deployment`가 별도로 실행되면 Settings의 Source를 확인한다. 별도 실행 로그만으로 충돌 원인을 확정하지 않는다.
- `scripts/prepare-pages.sh`는 `_site/index.html`, `_site/game/`, 이전 주소 호환용 `_site/게임/index.html`, `deploy-revision.txt`를 생성한다.
- `tests/pages.test.cjs`에서 배포 아티팩트 진입 파일과 HTML 내부 JS/CSS 경로를 검사하고, 엔진 테스트가 통과해야만 배포한다.
